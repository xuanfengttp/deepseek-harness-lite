原则：一律追加尾部，不插入中间，不修改已有。压缩是唯一重排时机。

③ 压缩：唯一重排窗口

正常: [sys][tools][user1][asst1][user2] miss 最后一轮 压缩: [sys][tools][Summary][recent] 前缀命中 →恢复append

Summary 放头部，之后追加不破坏其缓存。不在压缩前重排：被移动消息马上要压缩掉，重排代价无回收窗口。

④ 固定位置插入 vs Append：代价对比

设备状态注入、会话恢复 context 必须插在固定位置，损失多大？

Append 尾部追加

[sys][tools][user1][asst1][memory]

前缀全命中，只 miss 新增。命中率持续爬升。

固定位置插入

[sys][memory][user1][asst1]

插入点后全部 miss。已有对话缓存全失效。

场景能否 append说明
Memory recall✅ 可追加工具调用结果天然在尾部
Skill 切换⚠️ 改 systempersona 变化，后缀失效（低频）
设备状态注入❌ 需固定位置必须在 system 后、消息前
会话恢复 context❌ 需固定位置历史 context 需在对话前

⑤ Block 对齐：缓解固定插入的损失

Block 是 prefix matching 最小粒度，对齐 section 边界能否减少连带 miss？
未对齐: blk0blk1blk2blk3 [identity+rules | tools |persona|custom] ↑ section 跨 block 边界 对齐后: blk0blk1blk2blk3blk4 [identity+rules ] [tools] [persona] [custom] ↑ 边界 = block 边界

对齐后：persona 变化只 miss blk3+blk4，blk0~blk2 独立复用。未对齐：persona 跨 blk2 尾部，连带 miss。

  • 自部署 → 同款分词器 + block_size 已知 → 技术可行
  • 边界浪费 ≤ 15 token，占 system prompt ~5%
  • append-only 运行中无浪费，仅 section 变化时触发
储备方案：三层设计已达 85-99%，5% 边际收益暂不够。被迫固定插入场景增多或命中率瓶颈时再启用。
